Privacy Stack

Anonymity by Design

Five layered privacy enhancements beyond standard Monero, making transaction analysis computationally infeasible.

◎

Dynamic Ring Size

Ring size scales dynamically from 32 to 64 signers per transaction — 2–4× Monero's fixed 16. Makes statistical analysis exponentially harder.

ring-size: 32–64
▦

TX Padding

Each transaction's tx_extra is padded to a fixed 2500 bytes internally, removing size-based fingerprints. Network-layer relay padding is inherited from Monero (1024-byte granularity).

tx_extra: 2500B
⬡

Native Mixnet

Stem-phase relay biases transactions toward several sequential hops before broadcast, layered on top of Dandelion++ to obscure the originating node.

multi-hop stem
◈

Confidential Amounts

Transaction amounts are hidden on-chain by RingCT (Pedersen commitments), so observers cannot see how much value is being transferred.

RingCT
⟡

Stealth Addresses V2

Every payment is sent to a unique one-time address derived from the recipient's public keys, so on-chain observers cannot link transactions to a published address.

stealth-v2
⊛

Post-Quantum Ready

Dilithium3 + Kyber768 signature upgrade, now in development via a non-destructive hard fork targeted for 2027 — liboqs already integrated. Existing blockchain history is fully preserved.

Mining

Start Mining HRG

RandomX is CPU-optimised. Any modern processor can mine HIDERING. No ASICs, no GPU farms — just your CPU. Solo mining and the public pool both work today — pick whichever you prefer.

Requirements
  • OS   Linux x86_64 · macOS ARM64 · Windows x64 (see Releases below)
  • RAM   ≥ 2 GB free per mining thread (RandomX dataset)
  • DISK   ≥ 8 GB free (daemon pre-allocates ~5 GB LMDB)
  • PORT   19740 open inbound (optional, for relaying)

Optional: enable Linux huge pages for higher hashrate — echo 1280 | sudo tee /proc/sys/vm/nr_hugepages

Mining Pool

Prefer pooled mining? Point any RandomX miner (e.g. XMRig) at the HIDERING public pool for steady PPLNS payouts instead of waiting on a solo block. You still need a B-address to receive payouts — create one with steps 01 & 03 below.

  • STRATUMstratum+tcp://pool.hidering.org:3333
  • STATS APIpool.hidering.org:8117/stats
  • FEE1%

  • ALGORandomX (rx/0)

XMRig config example
// pools[] entry in your XMRig config.json
{
  "url": "pool.hidering.org:3333",
  "user": "YOUR_HRG_ADDRESS",
  "pass": "x"
}

Replace YOUR_HRG_ADDRESS with your own B-address. From the command line that is: xmrig -o pool.hidering.org:3333 -u YOUR_HRG_ADDRESS -p x -a rx/0

01

Download, verify, and extract

Grab the latest HIDERING release (v2.0.2) from the releases section below or directly on GitHub. Download both the archive and the matching .sha256 file into the same folder, then run the three commands below in order. Pick the archive for your platform: hidering-linux-x64.tar.gz (Linux x86_64), hidering-macos-arm64.tar.gz (macOS ARM64), or hidering-windows-x64.zip (Windows x64).

# 1. Verify the archive (must print: OK)
sha256sum -c hidering-linux-x64.tar.gz.sha256

# 2. Extract the archive
tar -xzf hidering-linux-x64.tar.gz

# 3. Move into the extracted folder
cd hidering-linux-x64/

Windows users: replace tar -xzf with a standard unzip or right-click → Extract All on the .zip file.

You are now inside hidering-linux-x64/, which contains the two binaries you will use in the next steps: ./hideringd (full node daemon) and ./hidering-wallet-cli (wallet CLI). Stay in this folder.

02

Launch the daemon & sync

Still inside hidering-linux-x64/ from step 01, start the daemon. It connects to seed nodes and syncs automatically. Keep this terminal open while mining — initial sync takes a few minutes on the current chain height.

# Run from the hidering-linux-x64/ folder
./hideringd \
  --add-priority-node seed1.hidering.org:19740 \
  --add-priority-node seed2.hidering.org:19740

Wait for: You are now synchronized with the network.

Both seed nodes run on dedicated VPS infrastructure with fixed IPs (seed1 → 135.125.243.137, seed2 → 207.180.211.96) and are managed by systemd for automatic restart on failure.

03

Create your wallet

Open a second terminal (leave the daemon running in the first one) and cd into the same hidering-linux-x64/ folder from step 01. Your address will start with B. Write down your 25-word seed phrase and keep it offline — without it your HRG cannot be recovered.

# In the second terminal, move into the extracted folder
cd hidering-linux-x64/

# Create a new wallet
./hidering-wallet-cli --generate-new-wallet my-wallet

# Or open an existing wallet
./hidering-wallet-cli --wallet-file my-wallet
04

Start mining

Inside the wallet CLI, launch the miner. Replace 4 with the number of CPU threads to allocate.

start_mining 4

Each block = 42.86 HRG credited to your wallet.

05

Stop mining & check balance

To stop at any time, use the commands below inside the wallet CLI. Mined HRG unlocks after 60 confirmations (~2 hours).

stop_mining # stop the miner
balance # view balance + unlocked
exit # close wallet safely
06

Send HRG to another wallet

Once your balance is unlocked, transfer HRG to any B-address. The fee is a fraction of a cent.

transfer B5xxx...address 10

show_transfers # transaction history

FAQ

Frequently Asked Questions

What is HIDERING?

HIDERING (HRG) is a privacy-focused cryptocurrency forked from Monero v0.18.1. It combines a Bitcoin-style fixed supply of 18 million coins with five enhanced privacy layers, making it one of the most private and auditable digital currencies available.

Why only CPU mining? No GPU or ASIC?

HIDERING uses RandomX, a proof-of-work algorithm specifically designed to be efficient on standard CPUs and inefficient on GPUs and ASICs. This ensures mining remains accessible to anyone with a regular computer, preventing the centralisation of mining power seen in Bitcoin and Ethereum.

What does "fair launch" mean?

Genesis (block 0) carries zero spendable reward, and emission follows a pure PoW schedule with no private sale, no seed round, and no team token allocation. After the 51% attack on the v1.x chain (see below), v2.0.0 introduces a short pre-public mining phase on a private network — founder nodes mine to harden the network before public opening, fund GUI / post-quantum development, and build a community reserve. Once the network opens publicly, every miner competes under the same rules: same RandomX algorithm, same block reward, same difficulty. No insider has access to coins that the public cannot also mine after launch.

How does the supply cap work?

The total supply is hard-capped at exactly 18,000,000 HRG. Mining starts at 42.86 HRG per block and halves every 210,000 blocks (~2.66 years). This is mathematically identical to Bitcoin's emission model, just with different parameters. Once the cap is reached, no new HRG can ever be created.

How do I store my HRG safely?

When you create a wallet with hidering-wallet-cli, you receive a 25-word seed phrase. Write it down on paper and store it in a secure, offline location. Anyone with access to your seed phrase can access your funds. Never store it on a connected device or share it with anyone.

Why are my mined coins locked?

Freshly mined coins require 60 block confirmations before they can be spent (~2 hours at 120 seconds per block). This is a standard blockchain security measure that prevents double-spending attacks. Your balance will show the total and the unlocked portion separately.

What is the post-quantum upgrade?

HIDERING is adding Dilithium3 and Kyber768 signatures via a non-destructive hard fork, targeted for 2027. Work is already under way — the liboqs library is integrated, PQ key types are defined, Dilithium3 TX signing and Kyber768 stealth addresses (BQ... format) are implemented and committed (May–June 2026) — all dormant until the HFv16 activation height. A full security audit was completed in June 2026. All existing coins and transaction history are fully preserved — only new transactions after the fork height will use the quantum-resistant scheme. No action is required from holders; simply updating the software is enough.

How do I choose my ring size?

By default, every transaction uses ring size 32 — the minimum on HIDERING, already 2× Monero's default of 16. For enhanced privacy, specify a larger ring size: transfer <address> <amount> 48 or transfer <address> <amount> 64. Higher ring sizes increase anonymity but slightly increase transaction size and fees.

Is HIDERING open source?

Yes. HIDERING is fully open source, forked from Monero v0.18.1. The complete source code, commit history, and genesis block are publicly verifiable on GitHub. Transparency is a core principle — anyone can audit the code, the supply, and every transaction on the network.

Why a v2.0.0? What happened?

Shortly after the v1.x launch, on 16 May 2026, the HIDERING network suffered a 51% attack — an external miner with greater hashing power than the rest of the network dominated the chain (then at height ~3577) and caused a major reorganisation, orphaning every block mined up to that point.

The main factor that made this attack possible was the absence of a stable, permanent public seed node. Without a fixed entry point with an invariant IP address, coordination between legitimate miners was fragile and the network was vulnerable to isolation.

v2.0.0 addresses this on two fronts: the Network ID changes from HRG\x01HIDERINGMAIN (magic 0x48524701) to HRG\x02HIDERINGMAIN (magic 0x48524702), immediately isolating the malicious miner. And a permanent seed node with a fixed IP is now operational, ensuring network stability for any new miner joining HIDERING.
